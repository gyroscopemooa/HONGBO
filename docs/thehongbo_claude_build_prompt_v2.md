# 더홍보(thehongbo.com) 웹사이트 제작 명령문

> 누구나 무엇이든 무료로 홍보하는 초간단 홍보 플랫폼 — Claude GUI 전달용 마스터 기획/구현 문서

이 문서는 통째로 Claude GUI에 전달하는 것을 전제로 작성되었습니다.

## 0. Claude에게 전달할 최상위 지시

너는 지금부터 www.thehongbo.com(서비스명: 더홍보)의 기획·디자인·프론트엔드·백엔드 구현 담당자다.

이 문서를 전체 요구사항의 단일 기준(Single Source of Truth)으로 사용한다. 아래에 적힌 범위를 임의로 확장하거나, SNS/커뮤니티/리워드 플랫폼처럼 과하게 만들지 않는다. 먼저 “누구나 무엇이든 홍보글을 쉽게 올리고, 방문자는 바로 발견해서 원래 링크로 이동하는 사이트”를 완성한다.

핵심 원칙은 단순하다.
1) 누구나 무료로 홍보할 수 있다.
2) 앱, 웹사이트, 서비스, 자영업/오프라인 가게, 상품/판매글, 콘텐츠/SNS, 이벤트/모집, 기타 자유홍보까지 전부 한 사이트에서 받는다.
3) 카테고리가 다르더라도 작성 폼과 카드 UI는 최대한 하나로 통일한다.
4) 글쓰기 과정은 짧고 쉽다.
5) 메인 화면은 처음부터 홍보물이 빽빽하게 보여야 한다.
6) 초기 실제 이용자가 없어도 사이트가 휑해 보이지 않도록 운영자 초기 콘텐츠를 충분히 넣는다.
7) 운영자 초기 콘텐츠를 공개 화면에서 굳이 “샘플”이라고 표시하지 않는다. 다만 실제 이용자가 작성한 것처럼 가짜 회원, 가짜 리뷰, 가짜 조회수, 가짜 구매/체험 수치를 꾸며내지는 않는다.
8) 첫 버전은 무료 홍보 게시판 자체에 집중하고, 결제·포인트·리워드·채팅·팔로우·복잡한 후기 시스템은 구현하지 않는다.

중요: 기존 프로젝트가 이미 존재하면 현재 구조와 스택을 먼저 분석하고, 가능한 한 최소 변경으로 통합한다. 새 프로젝트라면 아래 기술 권장안을 사용한다.

## 1. 서비스 정체성과 목표

서비스명: 더홍보
도메인: https://www.thehongbo.com
한 줄 정의: “앱도, 가게도, 사이트도, 물건도. 그냥 홍보하세요.”

이 사이트는 특정 업종 전문 플랫폼이 아니다. 인터넷에서 무언가를 알리고 싶은 사람이 홍보물을 무료로 게시하는 범용 홍보판이다.

사용 예시:
- 개인 개발자가 만든 앱을 올리고 Google Play/App Store 설치 링크로 유도
- SaaS/웹사이트/온라인 서비스를 소개하고 사이트 방문으로 유도
- 자영업자가 카페, 음식점, 미용실, 공방, 체육관, 스튜디오 등을 홍보
- 판매자가 본인 상품, 중고물품, 자체제작 상품, 쇼핑몰 상품 등을 홍보
- 유튜브, 블로그, 인스타그램, X, 틱톡 등 콘텐츠/SNS 계정을 홍보
- 이벤트, 체험단, 구인/모집, 오픈 소식 등을 홍보
- 위 어느 카테고리에도 딱 맞지 않는 것은 자유홍보로 등록

사이트의 가장 중요한 성공 기준은 “사이트에 들어오자마자 다양한 홍보물이 많이 보이고, 글 하나 올리는 데 부담이 없으며, 게시글을 누르면 원하는 외부 링크로 쉽게 이동한다”이다.

## 2. 디자인 방향 — 현재 승인된 컨셉샷을 기준으로

첨부된 컨셉 이미지를 전체적인 시각 방향의 기준으로 사용한다.

디자인 키워드:
- 한국형 포털/커뮤니티 느낌 + 현대적인 카드 UI
- 너무 스타트업 SaaS 랜딩페이지처럼 만들지 않는다.
- 흰색 배경 중심, 매우 옅은 회색/파스텔 보조 배경
- 브랜드 포인트 컬러는 선명한 레드/코랄 계열
- 카드 라운드, 얕은 그림자 또는 얇은 테두리
- 한 화면에서 여러 홍보물이 보이도록 정보 밀도는 적당히 높게
- “홍보 게시판” 느낌은 살리되 촌스럽지 않게
- 상단 히어로는 충분히 눈에 띄지만 화면 절반 이상을 독점하지 않게
- 데스크톱에서는 넓고 풍성하게, 모바일에서는 1~2열 카드로 자연스럽게 축소

메인 카피 기본안:
큰 제목: “홍보하고, 알려보세요!”
강조 문구: “더 많은 사람들에게, 더홍보”
보조 문구: “앱, 사이트, 가게, 상품, 서비스… 무엇이든 자유롭게 홍보할 수 있는 공간!”
CTA: “지금 홍보글 작성하기”
보조 포인트: “누구나 무료로 · 카테고리 제한 없이 · 간단한 작성으로 OK!”

카피는 이 톤을 유지하되 실제 UI 폭에 맞게 자연스럽게 조정해도 된다.

J. 관리자 페이지 /admin (일반 사용자에게 노출하지 않음)

## 4. 메인페이지 상세 구성

메인은 “소개 페이지”가 아니라 “홍보물이 실제로 돌아가는 포털 홈”처럼 보여야 한다. 아래 순서를 기본으로 한다.

[1] 최상단 헤더
- 좌측: 더홍보 로고
- 로고 옆 작은 문구: “세상의 모든 홍보가 여기에!” 또는 유사 문구
- 중앙: 검색창 “뭘 홍보하고 싶으신가요?” 또는 방문자 관점 “무엇을 찾고 있나요?”
- 우측: 로그인 / 내 홍보 / 글쓰기
- 글쓰기 버튼은 브랜드 포인트 컬러로 강하게 표시

[2] 2차 카테고리 네비게이션
- 전체보기 / 앱·게임 / 웹사이트 / 서비스 / 오프라인 가게 / 상품·판매 / 콘텐츠(SNS) / 이벤트·모집 / 자유홍보
- 우측에 인기글 / 최신글 / 지역별
- 스크롤 시 상단에 붙는 sticky 처리 가능

[3] 히어로
- 좌측: 강한 제목 + 소개 + CTA
- 우측: 승인된 컨셉샷처럼 사람/메가폰/스마트폰/홍보판을 연상시키는 친근한 일러스트 또는 그래픽
- 첫 버전에서 외부 유료 에셋 의존 금지. 직접 만든 단순 일러스트, 공개 사용 가능한 에셋, CSS/아이콘 조합 중 구현 가능한 방법 선택
- CTA 클릭 → /write

[4] 카테고리 바로가기 타일
- 8~9개 아이콘 타일
- 전체 / 앱·게임 / 웹사이트 / 서비스 / 오프라인 가게 / 상품·판매 / 콘텐츠(SNS) / 이벤트·모집 / 자유홍보
- 각 타일은 컬러를 조금씩 다르게 하되 전체 톤은 통일

[5] “오늘의 인기 홍보” 카드 섹션
- 데스크톱 기준 5~6개가 한 줄에 보이게
- 대표 이미지가 큰 카드
- 카드 구성: 대표 이미지 / 제목 / 한 줄 소개 또는 짧은 보조 문구 / 카테고리 배지 / 지역이 있으면 지역 배지
- 실제 조회 데이터가 충분히 쌓이기 전에는 adminPinned 또는 curated 플래그로 운영자가 선정한 글을 우선 노출
- 실제 데이터가 쌓인 후에는 최근 24~72시간의 유효 조회/클릭 데이터를 반영
- 가짜 조회수는 생성하지 않는다.

[6] “최신 홍보글” 리스트
- 왼쪽 또는 메인 영역
- 작은 썸네일 + 카테고리 배지 + 제목 + 짧은 설명 + 작성 시간
- 최근 글이 계속 아래로 이어짐
- “더보기” 클릭 시 /posts?sort=latest

[7] “실시간 인기글” 또는 “많이 보는 홍보” 랭킹
- 1~10위 정도의 간단한 텍스트 리스트
- 초기에는 운영자 추천 순서로 대체 가능
- 실사용 데이터가 쌓이면 자동 랭킹으로 전환

[8] 우측 사이드 영역(데스크톱)
- “지금, 당신의 홍보를 시작하세요!” CTA 배너
- 공지사항 3~5개
- 추가 프로모션 배너 1~2개
- 모바일에서는 본문 중간이나 하단으로 이동

[9] 푸터
- 더홍보 로고/한 줄 설명
- 이용약관 / 개인정보처리방침 / 운영정책 / 문의 / 광고문의(향후용)
- 회사/운영 정보는 실제 정보가 준비되지 않은 항목을 임의로 지어내지 않는다.

## 5. 홍보 카드의 통일 규칙

카테고리가 달라도 메인 카드 UI는 하나의 디자인 시스템으로 통일한다.

모든 글의 공통 카드 데이터:
- 대표 이미지 1장
- 카테고리
- 제목
- 한 줄 소개
- 링크 종류에 따라 달라지는 CTA 성격
- 선택: 지역
- 선택: 가격/판매가
- 실제 생성일

카드 CTA/상세 CTA 라벨은 카테고리에 따라 자동 변경:
- 앱/게임: “앱 설치하기” 또는 “다운로드/보러가기”
- 웹사이트: “사이트 방문하기”
- 서비스: “서비스 보러가기”
- 오프라인 가게: “매장 정보 보기” / 지도 링크가 있으면 “지도에서 보기”
- 상품/판매: “구매하러 가기”
- 콘텐츠(SNS): “콘텐츠 보기”
- 이벤트/모집: “참여/신청하기”
- 자유홍보: “바로가기”

주의:
- 카드에 너무 많은 메타데이터를 넣지 않는다.
- 연락처/주소/긴 설명은 상세 페이지로 보낸다.
- 썸네일이 없으면 카테고리별 기본 이미지/그래픽을 자동 사용한다.
- 이미지 비율은 전체 카드에서 동일하게 유지한다(예: 16:9 또는 4:3 중 하나로 통일).

## 6. 글쓰기 — “통합 폼 1개 + 필요한 경우만 추가 필드”

앱 전용 폼, 가게 전용 폼, 상품 전용 폼을 별도의 페이지로 만들지 않는다. 사용자는 한 개의 /write 화면에서 카테고리를 먼저 고르고 같은 흐름으로 작성한다.

공통 필수 항목:
1) 카테고리
2) 제목
3) 한 줄 소개
4) 상세 설명
5) 대표 이미지 1장
6) 외부 링크 1개

공통 선택 항목:
- 추가 이미지 최대 4장
- 지역
- 태그 최대 5개
- 연락 방법/연락처(사용자가 명시적으로 공개를 선택한 경우만)

카테고리별로 필요한 항목만 조건부 표시:
- 앱/게임: Google Play URL / App Store URL / 공식 사이트 URL 중 1개 이상. 플랫폼 선택(Android/iOS/Web/기타)
- 웹사이트: 사이트 URL
- 서비스: 서비스 URL, 이용 방식(온라인/오프라인/혼합) 선택 가능
- 오프라인 가게: 주소, 지도 링크(네이버지도/카카오맵/Google Maps 중 사용자가 가진 링크), 영업/문의 링크 선택
- 상품/판매: 가격(선택), 구매/판매 링크
- 콘텐츠(SNS): 플랫폼, 채널/게시물 URL
- 이벤트/모집: 신청 URL, 모집/행사 기간(선택)
- 자유홍보: 기본 링크만

중요 UX:
- 카테고리를 바꿔도 이미 입력한 공통 내용은 사라지지 않는다.
- 글 등록 전 실제 카드 모양의 미리보기 제공.
- 이미지 업로드 후 자동 크롭/미리보기 제공.
- 링크를 붙이면 가능할 경우 Open Graph 제목/설명/이미지를 불러와 작성 보조. 실패해도 글쓰기 자체가 막히면 안 된다.
- 외부 링크는 서버에서 위험한 scheme(javascript:, data: 등)을 차단하고 http/https만 허용.
- 이미지 없이 작성하려는 경우에는 카테고리 기본 이미지 사용 여부를 안내한다. 디자인상 대표 이미지 1장 등록을 적극 권장하지만 UX가 너무 막히지 않게 기본 이미지를 허용해도 된다.

## 7. 로그인/회원 구조

사이트 탐색과 외부 링크 클릭은 비회원에게 완전히 공개한다.

글 작성/수정/삭제를 위해서는 로그인한다.
초기 인증은 Google 로그인 하나를 우선 제공한다.
- “Google로 계속하기” 한 버튼 중심
- 이메일/비밀번호 자체 회원가입은 첫 버전에서 만들지 않아도 됨
- 인증은 Supabase Auth 또는 기존 프로젝트 인증 시스템 활용

공개 프로필은 최소화한다.
- 실제 Google 이름/이메일을 게시글 카드에 자동 노출하지 않는다.
- 사용자는 닉네임을 선택할 수 있다.
- 닉네임을 설정하지 않은 경우 “홍보회원” 계열의 표시명을 자동 생성하거나 작성자 영역 자체를 최소화한다.

완전 익명 무계정 글쓰기는 구현하지 않는다.
이유: 도배/스팸/불법광고, 수정·삭제 권한 문제, 신고 대응 문제를 줄이기 위해서다.

마이페이지는 복잡하게 만들지 않는다.
- 내가 작성한 홍보글 목록
- 상태(게시중/숨김/차단/만료)
- 수정
- 삭제
- 다시 홍보하기(갱신)

프로필 꾸미기, 팔로우, 친구, DM은 만들지 않는다.

## 8. 상세페이지

상세 페이지는 홍보물을 읽고 최종 외부 행동을 유도하는 페이지다.

구성:
- 카테고리/지역 배지
- 제목
- 한 줄 소개
- 대표 이미지
- 추가 이미지 갤러리(있을 때만)
- 상세 설명
- 가격(상품일 때만)
- 주소/지역(오프라인일 때만)
- 지도 링크 버튼(있을 때만)
- 외부 이동 CTA(카테고리에 맞는 라벨)
- 게시일
- 태그
- 신고하기
- 작성자 본인에게만 수정/삭제 버튼
- 같은 카테고리의 다른 홍보 4~6개 추천

외부 링크는 새 탭으로 열고 rel="noopener noreferrer" 처리.
사용자가 외부로 이동한다는 것을 CTA 주변에 과하게 경고할 필요는 없지만, 링크 주소 도메인을 작게 표시하는 것은 가능.

댓글은 첫 버전에서 제외한다.
후기/별점도 첫 버전에서 제외한다.

## 9. 검색/필터/지역

검색은 제목, 한 줄 소개, 상세 설명, 태그를 대상으로 한다.

필터는 단순하게 유지:
- 카테고리
- 최신순
- 인기순
- 지역(지역 정보가 있는 글만)

지역 필터는 전국 행정구역 전체를 처음부터 복잡한 계층 UI로 만들 필요 없다.
- 시/도 수준부터 시작 가능: 서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주
- 주소가 있는 오프라인 글은 지역을 자동 추정할 수 있으면 보조하되, 사용자가 직접 선택 가능
- 온라인 앱/웹사이트 글에는 지역을 강제하지 않는다.

메인에 지역별 탭을 크게 넣기보다는 상단 “지역별” 메뉴에서 필터 페이지로 연결한다.

## 10. 초기 콘텐츠 — 첫날부터 꽉 찬 사이트처럼 보이게

실사용자가 없더라도 메인이 비어 보이지 않게 “운영자 초기 홍보 콘텐츠(seed content)”를 충분히 생성한다.

중요 운영 원칙:
- 공개 UI에서 모든 글에 “샘플” 스티커를 붙일 필요는 없다.
- 다만 존재하지 않는 실사용자 계정/후기/구매/조회수/리뷰를 만들어 실제 활동처럼 속이지 않는다.
- 초기 글은 내부적으로 source='seed' 또는 is_seed=true로 구분해 나중에 쉽게 교체/삭제 가능하게 한다.
- 카드에서 작성자 표시가 꼭 필요하지 않다면 초기에는 작성자를 눈에 띄게 보여주지 않는다.
- 실제 이용자 글이 늘어나면 운영자 초기 글은 자연스럽게 뒤로 밀리거나 일부만 유지한다.

초기 데이터 목표:
- 최소 36개 홍보글
- 카테고리별 최소 4개 이상
- 메인 인기/추천 영역용 8~12개
- 메인 최신 리스트가 스크롤해도 비지 않을 정도
- 4~6개의 배너
- 공지사항 3~4개

초기 글 예시(실제 존재하는 제3자 업체를 허가 없이 홍보하는 식으로 만들지 말고, 서비스 소유 콘텐츠 또는 명백히 일반적인 가상 콘텐츠로 구성):

앱/게임
- “실시간 방송 번역 앱 TranStream” — 해외 라이브/영상 실시간 자막 번역 소개
- “하루 10분 습관 체크 앱” — 루틴/체크리스트 앱 소개
- “사진 한 장으로 오늘 메뉴 추천” — 가벼운 라이프스타일 앱
- “짧게 즐기는 캐주얼 퍼즐게임”
- “여행 회화 메모 앱”

웹사이트
- “AI로 이력서 초안을 다듬는 웹서비스”
- “무료 이미지 사이즈 변환 도구”
- “링크 하나로 포트폴리오 만드는 페이지”
- “동네 행사 모아보는 웹사이트”
- “간단 견적 요청 페이지”

서비스
- “소상공인 무료 첫 상담”
- “1인 사업자 상세페이지 점검”
- “온라인 문서 정리 대행”
- “영상 자막 정리 서비스”
- “홈페이지 사용성 피드백”

오프라인 가게
- “울산 삼산동 감성 카페”
- “부산 서면 수제버거 가게”
- “서울 성수 소형 공방”
- “대전 1:1 PT 스튜디오”
- “대구 예약제 미용실”

상품/판매
- “데스크 정리용 미니 수납함”
- “캠핑용 경량 랜턴”
- “무선 이어폰 파우치”
- “직접 만든 캐릭터 스티커 세트”
- “원두 드립백 세트”

콘텐츠(SNS)
- “퇴근 후 1분 생활팁 쇼츠 채널”
- “직장인 개발 기록 블로그”

이벤트/모집

- “서비스 사용성 인터뷰 참가자 모집”

자유홍보

- “팀 프로젝트 멤버를 찾습니다”

초기 콘텐츠 이미지:
- 각 글마다 동일 이미지를 돌려쓰지 않는다.
- 직접 생성한 추상/일러스트/제품 목업/카페 분위기 이미지 등으로 다양성을 준다.
- 제3자의 상표/로고/저작권 이미지를 임의로 복제하지 않는다.
- 이미지 파일은 최적화(webp/avif 가능), alt 텍스트 제공.

초기 배너 예시:
1) “뭐든 홍보하세요. 등록은 무료!” → /write
2) “앱 만들었는데 알릴 곳이 없다면?” → /category/apps
3) “우리 가게, 동네 사람들에게 알려보세요.” → /category/offline
4) “상품·서비스·콘텐츠까지 한 번에” → /posts
5) “새로운 홍보를 매일 발견하세요.” → /posts?sort=latest

공지 예시:
- “더홍보 오픈 안내”
- “홍보글 작성 시 꼭 확인해주세요”
- “불법·사기·성인·도배 홍보는 삭제될 수 있습니다”
- “외부 링크 이용 시 거래 조건을 직접 확인해주세요”

## 11. 초기 인기/추천 로직 — 유저가 적어도 어색하지 않게

메인의 “오늘의 인기 홍보”가 실제 유저가 거의 없을 때 0조회 글만 보여주며 어색해지는 문제를 방지한다.

로직:
1) admin_pinned=true인 글이 있으면 우선 표시
2) pinned가 부족하면 운영자 큐레이션 점수(curated_rank)가 있는 글 사용
3) 실제 조회/클릭 데이터가 일정량 이상 쌓이면 최근 24~72시간의 유효 이벤트를 계산해 인기순으로 자동 전환

유효 이벤트는 봇/새로고침 도배를 최대한 제외한다.
같은 익명 방문자의 반복 조회는 일정 시간 동안 중복 카운트 제한 가능.

메인에 숫자를 반드시 표시할 필요는 없다.
초기에는 카드에 조회수를 숨기거나, 실제 값만 표시한다.
“인기”라는 섹션명은 운영자 추천 콘텐츠를 포함할 수 있도록 UI 문구를 “오늘의 인기 홍보” 또는 “주목받는 홍보” 중 자연스럽게 선택한다.

## 12. 관리자 기능

/admin은 최소한의 운영 도구를 제공한다.

필수:
- 전체 글 목록
- 검색/카테고리/상태 필터
- 글 숨김/복구
- 글 삭제
- 사용자 차단 또는 작성 제한
- 신고 목록 확인 및 처리
- 추천/메인 고정(admin_pinned)
- 큐레이션 순서(curated_rank) 조정
- 공지 작성/수정/삭제
- 배너 관리(이미지, 제목, 링크, 노출 여부, 순서)
- 초기 seed 글 구분 필터

스팸 대응:
- 계정당 짧은 시간에 과도한 연속 등록 제한
- 동일 URL 반복 등록 제한 또는 경고
- 금지 키워드/위험 URL 기본 필터
- 신고 누적 시 임시 숨김 여부는 과도한 오탐이 없도록 관리자 확인형을 우선

관리자에서 결제/광고 상품 판매 기능은 첫 버전에서 만들지 않는다.

## 14. 추천 기술 스택

새 프로젝트라면 다음을 우선 고려:
- Next.js 최신 안정 버전, App Router
- TypeScript
- Tailwind CSS
- Supabase: Auth + Postgres + Storage
- Google OAuth
- 이미지 최적화: Next/Image 또는 동등 기능
- 배포: 현재 운영 환경과 맞는 Cloudflare/Vercel 중 하나. 기존 인프라가 있다면 새 플랫폼을 억지로 추가하지 않는다.

반드시 지킬 것:
- 모바일 우선 반응형
- SEO 가능한 서버 렌더링/메타데이터
- 카테고리/게시글별 canonical URL
- Open Graph/Twitter 카드 메타
- sitemap.xml / robots.txt
- 게시글 slug 또는 안정적인 id URL
- 이미지 lazy loading
- 리스트 페이지 pagination 또는 cursor 방식
- 기본 접근성: label, alt, focus state, 키보드 사용

외부 링크 Open Graph 자동 추출은 서버측 fetch를 사용할 경우 SSRF 방어를 해야 한다.
- localhost / private IP / metadata endpoint 접근 금지
- timeout
- 최대 응답 크기 제한
- content-type 확인

기존 프로젝트가 있으면 기존 인증/DB/컴포넌트 시스템을 우선 재사용한다.

## 15. 모바일 UX

모바일에서 별도 앱처럼 과하게 재설계하지 말고 같은 서비스 구조를 유지한다.

- 헤더: 로고 + 검색 아이콘 + 글쓰기 강조
- 카테고리 메뉴: 가로 스크롤 칩 또는 2행 타일
- 히어로는 높이를 줄이고 CTA를 먼저 보이게
- 인기 홍보: 2열 카드 또는 가로 스크롤 카드
- 최신 홍보: 1열 리스트
- 사이드바의 배너/공지: 최신 리스트 사이 또는 하단에 재배치
- 글쓰기 폼: 한 열, 큰 터치 영역, 이미지 업로드 편리하게
- 외부 이동 CTA는 상세페이지에서 화면 하단 sticky 버튼 사용 가능
- 긴 설명/태그가 레이아웃을 깨지 않게 line clamp 처리

## 16. 운영정책/금지 콘텐츠 최소 장치

“무지성 홍보”라는 컨셉은 무엇이든 쉽게 홍보한다는 의미이지 불법/위험 게시물을 허용한다는 뜻이 아니다.

최소 금지 범주를 운영정책에 명시:
- 불법 상품/서비스
- 사기, 피싱, 악성코드, 개인정보 탈취
- 성적 착취/불법 성인 콘텐츠
- 폭력·불법 도박 등 법률상 문제 콘텐츠
- 명백한 타인 사칭
- 반복 도배/자동 스팸
- 권리 침해 신고가 접수된 콘텐츠

외부 거래는 더홍보가 판매 당사자가 아니라는 점을 명시.
사용자 신고 버튼은 모든 상세페이지에 배치.

MVP에서 완벽한 자동 심사 시스템을 만들려고 하지 말고, 기본 필터 + 신고 + 관리자 수동 처리 구조로 시작한다.

## 17. 글 만료/갱신

홍보글이 영구히 쌓여 죽은 링크 천지가 되는 것을 막기 위한 가벼운 갱신 구조를 넣는다.

권장:
- 기본적으로 30~60일 후 갱신 알림 또는 상태 확인
- 첫 버전에서는 자동 삭제보다 “만료/숨김” 처리 권장
- 작성자는 마이페이지에서 “다시 홍보하기”를 눌러 날짜를 갱신
- 갱신 시 무조건 인기 1위로 올리지는 말고 최신글 노출 기준만 재계산
- 운영자가 seed 글의 만료 제외 여부를 제어 가능

기간은 설정값으로 관리해 나중에 쉽게 변경할 수 있게 한다.

## 18. 절대 하지 말 것 — MVP 범위 고정

다음 기능은 현재 구현하지 않는다. DB나 화면에 미완성 버튼도 함부로 만들지 않는다.

- 포인트/현금 리워드
- 사용자에게 돈 주고 리뷰 작성시키는 기능
- 결제/유료 부스팅/광고 구매
- 복잡한 등급제
- 1:1 채팅/DM
- 팔로우/친구
- 댓글 커뮤니티
- 별점/리뷰 시스템
- 거래 에스크로
- 자체 배송/주문
- 네이버/카카오 지도 API의 복잡한 지도 탐색 UI
- 업종별 완전히 다른 작성 폼
- 업체별 전용 미니홈피 빌더
- AI 기능을 이유 없이 여러 개 붙이기
- 대시보드 분석 기능 과도하게 만들기

나중에 트래픽과 수요가 확인되면 확장한다. 지금 목표는 “홍보글 등록 → 메인/목록 노출 → 상세 → 외부 클릭” 루프 완성이다.

## 19. 세부 UX 규칙

- 글쓰기 버튼은 모든 주요 화면에서 쉽게 찾을 수 있어야 한다.
- 비회원이 글쓰기 클릭 → Google 로그인 → 인증 성공 후 원래 /write로 복귀.
- 저장 실패 시 작성 내용이 최대한 보존되게 한다.
- 삭제는 확인 모달을 띄운다.
- 외부 링크 오류/삭제된 글은 관리자에서 빠르게 숨길 수 있게 한다.
- 빈 검색결과에는 “홍보글 작성하기” CTA를 보여준다.
- 카테고리 목록이 비어 있을 때도 seed 콘텐츠 또는 다른 카테고리 추천을 보여 사이트가 끊겨 보이지 않게 한다.
- 디자인 내 모든 버튼 문구는 한국어를 기본으로 한다.
- 날짜 표기는 “3분 전 / 2시간 전 / 3일 전” 상대 시간 + 상세에서는 절대 날짜도 가능.
- 제목/설명에 HTML을 직접 허용하지 않는다. 안전한 텍스트/제한된 Markdown을 사용한다면 sanitize 필수.
- 이미지 업로드 실패, 링크 메타데이터 실패, 로그인 취소 등 오류 상태를 사용자에게 이해하기 쉽게 표시.

## 20. SEO와 공유

이 사이트는 검색 유입이 매우 중요하므로 게시글 자체가 검색 결과에 잡히도록 만든다.

- 각 게시글 title: “[홍보 제목] | 더홍보”
- meta description: 한 줄 소개를 기본 사용
- OG image: 대표 이미지
- 카테고리별 meta title/description
- JSON-LD는 카테고리에 맞는 안전한 범위에서 적용 가능하나 과도한 구조화 데이터 스팸 금지
- 검색엔진에 차단해야 하는 관리자/마이페이지/작성 페이지는 noindex
- 게시글 삭제/숨김 시 적절한 404/410 처리 전략
- 공유 버튼은 필수는 아니지만 “링크 복사” 정도는 상세페이지에 추가 가능

## 22. 완료 기준(Definition of Done)

아래를 모두 만족해야 1차 완성으로 본다.

[메인]
- 승인된 컨셉샷과 유사한 풍성한 포털형 홈
- 히어로/카테고리/인기 홍보/최신글/랭킹/배너/공지/푸터 존재
- 초기 콘텐츠가 충분히 있어 빈 공간이 거의 없음

[글쓰기]
- Google 로그인 후 작성 가능
- 통합 폼 하나로 모든 카테고리 등록 가능
- 카테고리에 따라 조건부 필드만 추가 표시
- 이미지/링크/제목/설명 저장 정상
- 작성 완료 후 상세페이지로 이동

[목록/상세]
- 전체/카테고리/검색/최신/인기 탐색 가능
- 카드 UI 통일
- 상세에서 외부 링크 버튼 정상
- 모바일/데스크톱 정상

[사용자 관리]
- 내 글 목록
- 수정/삭제/갱신
- 다른 사람 글 수정 불가

[운영]
- 신고 가능
- 관리자 숨김/삭제/추천 가능
- seed 글 구분 가능
- 배너/공지 수정 가능

[품질]
- 빌드 성공
- 타입 오류 없음
- 주요 콘솔 오류 없음
- 이미지 깨짐 없음
- 빈 상태/에러 상태 처리
- SEO 기본 메타 적용
- 개인정보/외부 링크 기본 보안 적용

## 23. Claude의 최종 작업 방식 지시

이 문서를 읽고 바로 코드를 무작정 대규모 수정하지 말고, 먼저 현재 저장소를 분석해 다음을 내부적으로 확인한다.
- 현재 스택
- 기존 인증 여부
- DB/스토리지 여부
- 기존 라우팅/디자인 시스템
- 배포 환경

그 후 이 문서의 요구사항을 기준으로 가장 작은 변경으로 완성한다.

중요:
- 내가 요구하지 않은 기능을 “좋아 보인다”는 이유로 임의 추가하지 말 것.
- 데이터 구조와 UI는 나중에 확장 가능하게 하되 지금은 단순하게 유지할 것.
- 구현 중 선택지가 생기면 “홍보글을 빠르게 올리고 많이 보여주는 것”을 최우선 판단 기준으로 삼을 것.
- 데스크톱만 예쁘고 모바일이 무너지지 않게 할 것.
- 초기 seed 콘텐츠를 실제 DB 또는 명확한 seed 스크립트로 넣어, 새 배포 직후 메인이 빈 화면이 되지 않게 할 것.
- 초기 콘텐츠는 운영 데이터와 구분 가능한 내부 플래그를 둘 것.
- 실제 사용자가 쌓이면 seed 콘텐츠를 쉽게 숨기거나 삭제할 수 있게 할 것.
- 실제 사용자 수, 조회수, 리뷰, 판매량을 임의로 조작하지 말 것.

작업 후 반드시 다음을 보고한다.
1) 구현한 화면 목록
2) 수정/추가한 주요 파일
3) DB 마이그레이션/환경변수
4) 내가 직접 해야 하는 외부 설정(Google OAuth, Supabase URL/키, 도메인 DNS 등)
5) 테스트 결과
6) 아직 남은 항목이 있다면 그 이유와 정확한 위치

최종 목표는 “기능 많은 스타트업 서비스”가 아니라, 처음 보는 사람이 들어와도 이미 활발한 홍보판처럼 보이고 누구나 1분 안에 자기 홍보글을 올릴 수 있는 www.thehongbo.com이다.
