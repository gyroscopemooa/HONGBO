[제목]
기존 홍보글을 다시 알리고 싶을 때, 수정과 다시 홍보하기 중 무엇을 써야 하나요?

[주제]
promotion (홍보 시작하기)

[이 글이 해결하는 질문 하나]
이미 등록한 홍보글의 내용을 고치거나 다시 노출하고 싶을 때 어떤 기능을 사용해야 하나요?

[첫 문단의 답]
가격·이용 조건·설명·링크를 바꾸려면 ‘수정’을, 기존 글의 최신글 노출 기준과 노출 기간을 갱신하려면 ‘다시 홍보하기’를 사용하세요. 내용도 오래됐고 다시 알리고 싶다면 먼저 설명을 수정한 뒤 다시 홍보하기 가능 여부를 확인하면 됩니다. 같은 링크의 글을 새로 복제할 필요는 없습니다. 다시 홍보하기는 본문을 고쳐주거나 인기 순위 상승을 보장하는 기능이 아닙니다.

[따라 할 수 있는 방법]
준비할 것
해당 홍보글을 작성한 계정으로 로그인하고, 변경할 정보와 현재 연결 주소를 준비합니다. 아래 안내는 더홍보 운영팀이 현재 구현을 확인해 작성했으며, 홍보 효과를 측정한 사용 후기는 아닙니다.

1. ‘내 홍보’에서 기존 글을 찾습니다.
새 글쓰기 화면을 열기 전에 내가 작성한 글이 있는지 확인하세요. 같은 링크로 공개 중인 글을 다시 등록하면 중복 등록 안내가 나올 수 있습니다. 기존 글을 활용하면 이미 공유한 상세 페이지 주소도 유지할 수 있습니다.

2. 내용이 달라졌다면 ‘수정’을 누릅니다.
가격, 신청 기간, 제공 범위, 이용 방법처럼 독자의 판단에 영향을 주는 정보를 먼저 바로잡으세요. 연결 주소도 직접 열어 현재 서비스나 안내로 이동하는지 확인합니다. 필요한 내용을 고친 뒤 ‘수정 완료’를 누릅니다. 이 작업은 기존 글을 편집하는 것이므로 새 글을 만들지 않습니다.

3. 다시 알리고 싶다면 ‘다시 홍보하기’를 확인합니다.
내 홍보 목록의 해당 글에 버튼이 표시되는지 확인한 뒤 누릅니다. 성공하면 최신글 정렬에 쓰는 기준 시각과 노출 기간이 갱신됩니다. 현재 설정상 노출 기간은 갱신 시점부터 60일입니다. 제목·본문·연결 링크는 이 버튼으로 바뀌지 않으므로, 정보가 오래됐다면 먼저 수정해야 합니다.

4. 결과 안내와 글 내용을 확인합니다.
‘다시 홍보하기가 완료됐어요!’라는 안내가 나오면 글의 상세 페이지와 연결 링크를 다시 확인하세요. 이용자가 반복해서 묻는 내용이 있다면 설명에 답을 보완합니다. 같은 문구의 글을 여러 개 만드는 것보다 기존 글 하나의 정보가 정확한지 확인하는 데 집중해 주세요.

[안 되는 경우와 대안]
‘하루에 한 번만 할 수 있어요’라는 안내가 나오는 경우
현재 공개 상태인 글은 마지막 최신글 기준 시각에서 24시간이 지나지 않으면 다시 홍보하기가 제한됩니다. 날짜가 바뀌었다고 바로 가능한 것은 아닙니다. 예를 들어 오늘 오후 3시에 등록하거나 갱신한 공개 글이라면 다음 날 오후 3시 이후에 다시 시도하는 방식입니다. 기다리는 동안 필요한 내용 수정은 별도로 진행할 수 있습니다.

버튼이 보이지 않거나 권한 안내가 나오는 경우
먼저 그 글을 작성한 계정으로 로그인했는지 확인하세요. 다시 홍보하기는 작성자 본인의 글에 사용하는 기능입니다. 숨김·차단 처리된 글은 다시 홍보할 수 없고, 삭제된 글도 대상으로 사용할 수 없습니다. 상태가 이해되지 않으면 글 주소와 화면에 나온 안내를 정리해 문의해 주세요.

노출 기간이 지난 경우
‘내 홍보’에서 글의 상태와 다시 홍보하기 버튼을 확인하세요. 기간이 끝난 글도 현재 화면에서 갱신 가능한 상태인지 확인하는 것이 먼저입니다. 새 글을 복제하거나 링크를 바꿔 제한을 피하려고 하기보다 기존 글의 내용과 상태를 점검해 주세요.

다시 홍보했는데 인기 순위나 방문자가 늘지 않는 경우
다시 홍보하기는 최신글 기준과 노출 기간을 갱신합니다. 조회수·클릭 수를 늘려주는 기능이 아니며, 인기 순위나 외부 검색 순위 상승도 보장하지 않습니다. 제목이 전달하는 내용과 실제 서비스가 일치하는지, 필요한 이용 조건이 빠지지 않았는지 먼저 확인하세요.

[추가 확인 사항 — 관리자 전용 메모]
2026-10-30 기준 운영 DB를 읽기 전용 조회하여 공개 커뮤니티 글이 1편임을 확인했다. 기존 글은 첫 등록 준비를 다루고, 수정·갱신은 짧게 언급하므로 본 원고는 등록 이후의 선택과 제한을 상세히 설명하는 별도 질문으로 구성했다.
검색 실적 CSV, 검색량, 사용자 문의 빈도 자료는 제공되지 않았다. 검색 수요·인기도·성과가 검증됐다는 주장은 하지 않는다.
확인한 구현: src/app/actions/posts.ts의 renewPostAction, src/components/OwnerActions.tsx, src/app/mypage/page.tsx, src/lib/store/supabase.ts의 renewPost, src/lib/constants.ts의 postLifetimeDays, src/lib/queries.ts의 postExpiryFromNow.
기존 글과 문의 링크의 HTTP 200 응답을 확인했다. /mypage는 로그인 전 /auth?next=%2Fmypage로 연결됨을 확인했다.
현재 갱신 조건·60일 설정은 코드로 확인했다. 운영 게시글의 실제 수정·갱신 버튼을 누르는 변경 테스트는 하지 않았다. 발행 전 별도 테스트 글로 동작을 확인하면 좋다. 특히 화면에 만료로 보이지만 저장 상태가 active인 글에는 active의 24시간 조건이 적용될 수 있어 ‘만료 글은 무조건 즉시 갱신된다’고 단정하지 않는다.
발행 후 확인: 독자가 수정과 갱신의 차이를 이해하는지, 같은 질문이 반복되는지, 내 홍보 이용으로 이어지는지 확인한다. 커뮤니티 전용 클릭·전환 집계가 자동 연결돼 있다고 설명하지 않는다.

새 글에는 위 기존 글의 확인된 주소를 이미 포함했습니다. 기존 글에는 새 글 공개 후 링크를 추가하면 양방향 연결이 됩니다. 기존 글 URL은 유지합니다. 같은 주제의 최근 글 영역은 공개 후 자동 조회되지만 기존 본문과 관련 안내 필드는 자동 수정되지 않습니다.

[실행 결과]
사용자의 직접 승인 후 기존 서버 전용 관리 경로로 공개 발행하고 기존 글의 관련 문장·링크를 보완했습니다. 중복 검사와 동시 수정 방지 조건을 적용했고 DB 재조회로 양방향 링크를 확인했습니다.
DB 기반 콘텐츠로 운영 페이지에 즉시 반영됩니다. 실행 코드 변경이 없어 추가 Worker 배포는 필요하지 않습니다. 유료 API·무인 예약 자동화는 연결하지 않았습니다.
